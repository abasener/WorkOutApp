# Screen: Settings

## Implemented
- **Data set: Personal / Demo toggle** — a pill switch at the top of the screen, backed by two entirely separate SQLite files (`terpinlift_personal.db` / `terpinlift_demo.db`, see `01_DATA_MODEL.md` "Personal vs. demo data set"), not a filter over one shared database — so switching can never mix or overwrite the other set. Switching to Demo always reseeds a clean synthetic set first (confirm dialog explains this) — toggling off and back on is the "start over" gesture. Switching to Personal never touches anything, just reopens that file as-is. The active choice persists across restarts via a plain marker file (`ProfileManager`), independent of either database.
- **Profile: Gender toggle (Female/Male)** — defaults to Female (matches how this app was framed from the start), persisted in `app_settings` (`gender` key), read via `UserProfile.gender`. Feeds the bodyweight-ratio strength-standard Goal gauge on Lift detail (`07_SMART_TRENDS.md`) — not used or shown anywhere else.
- **Profile: Birth year** (plain number field, validated 1900–current year) — persisted in `app_settings` (`birth_year` key). Converted to a broad `AgeBucket` (`UserProfile.ageBucket`: under-20 / 20s / 30s / 40s / 50s / 60+) rather than an exact age, per the user's call — a bucket-based multiplier on the strength standards, not a precise age-graduated formula. Unset defaults to the 20s/reference bucket (no age adjustment) rather than blocking the Goal feature.
- **Units toggle (lb/kg)** — a pill switch; persisted in `app_settings` (`weight_unit` key). All weight is stored canonically in lb; this only controls display via the shared `Units` helper (see `00_UX_DESIGN.md`).
- **Hide my weight** — a switch in the same Units card; persisted in `app_settings` (`hide_weight` key). Masks **only the user's own bodyweight** — the Metrics weekly-bodyweight chart axis and the Days-tab bodyweight rows — as a masked "---lb"/"---kg" placeholder via `Units.formatMaskable`; trend shapes still show, just not the printed number. Lift weights (squat, bench, e1RM/PR, Strength Goal gauge, session history) are **never masked** — they always use `Units.format` — since the original implementation over-applied `formatMaskable` to those too, which was a bug (bodyweight-privacy intent, not a general weight-privacy toggle) fixed after on-device testing surfaced the miscommunication. Entry/edit forms are deliberately unaffected (you need the real number to log or correct one). Off by default, matching prior behavior.
- **Export data** — dumps every table (including `app_settings`) from the **active profile's** database to a JSON file in the app's documents folder (`terpinlift_export.json` for Personal, `terpinlift_export_demo.json` for Demo — separate filenames so one can never overwrite the other).
- **Import data** — restores from that same profile-scoped export file (fresh-install restore, not a smart merge).
- **Wipe Data** — confirm dialog, then deletes all logged lifts/bodyweight/metrics/cycle entries from the **active profile only** but keeps its exercise list intact.
- **Reset Demo Data** — only enabled while Demo is the active data set (switch to it above first); confirm dialog, then fully wipes (including exercises) and generates ~2 months of synthetic history across every tracked thing (lifts with varying effort/RPE, steps, sleep, soreness, bodyweight, cycle flow) so trends/predictions can be reviewed without waiting on real data. Personal data is a different file and is never touched. See `TestDataService`.

## Not yet built
- **Rolling window config** — the short/long trend windows (default 7d / 28d, see `08_GLOSSARY_AND_SCIENCE.md`) aren't exposed as adjustable settings yet; still hardcoded where used.
- Cycle-tracking visibility toggle (hide the Metrics card entirely / PIN-lock it) — still just relies on the card being nondescript, per `00_UX_DESIGN.md`.
- Fitbit account connection/auth management, once that integration is scheduled.
