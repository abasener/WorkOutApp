# Design Files

Planning docs, kept up to date as the plan evolves (chat context gets compacted over time — these files are the durable record). The actual Flutter project lives in `TerpinLift/`.

- `00_UX_DESIGN.md` — overall vibe, display philosophy (icon → plot → words), chart conventions (adaptive polynomial/moving-average trends), units system, soreness body map + lift muscle diagrams, nav structure, privacy/notification rules.
- `01_DATA_MODEL.md` — SQLite schema (tables, columns, migration notes).
- `02_SCREEN_home.md` / `03_SCREEN_lifts.md` / `04_SCREEN_quick_log.md` / `05_SCREEN_metrics.md` / `06_SCREEN_settings.md` / `09_SCREEN_cycle_detail.md` — one doc per screen.
- `07_SMART_TRENDS.md` — the layered plan for rule-based → RPE-weighted trend analysis (the "not-quite-AI" engine). No workout-planning logic — this only judges recovery/prediction, never picks exercises for you.
- `08_GLOSSARY_AND_SCIENCE.md` — plain-language source text for in-app "i" tooltips (RPE, e1RM, soreness, etc.) plus the sports-science reasoning behind each formula.
- `10_WORKOUT_PLANNER.md` — decision doc + status for a movement-pattern-based session builder (phase 1 implemented, phases 2-3 not started). Deliberately scoped as a sorter, not a scheduler, to stay consistent with the "never picks exercises for you" rule above.

## Status
Core app is built and running (`TerpinLift/`): logging (93 seeded lifts — barbell compounds including Olympic-style jerks/snatch, isolation accessories, bodyweight movements, named machines/cables, one cardio entry — + custom movements), sets/sessions with a **0-10 "reps left" effort field** (0 = true failure/"tried one more and couldn't," 9 and 10 both collapse to the RPE floor since past ~8 left the distinction stops meaning anything), a searchable exercise picker (defaults to pinned, typing searches the full library) used both for quick-log and for reassigning a logged session's exercise, per-session notes, edit/delete on any logged session, a quick "+" log-set button on Lift detail.

**Add/edit exercise (2026-07-16):** adding a new custom movement is a 3-step wizard (name+tags, muscle selection, optional goal+notes) — only name and picking at least one muscle are required, everything else skippable. Editing an existing exercise stays single-page. Movement-pattern tags are **not** user-editable from the app at all (backend/seed-data only — they only drive the Workout Planner's pattern-pool matching). Each exercise can carry **user-set fine-grained target muscles** (`MuscleSelectorSheet` — full front+back body-map tap targets, not just broad groups), falling back to curated defaults for older seeded lifts that haven't had this set. The old curated per-lift "Overview" cues are gone entirely, replaced by **free-text personal notes** the user writes themselves.

A **Workout Planner (phases 1-2)** — a "Plan a session" card on Home (dark when idle, turns red when a session's active) → Day Select (days from a seeded default template matching a real gym-plan PDF, most-overdue-first) → the Active Day page (elapsed timer, a soft per-slot progress bar, a notes field, one card per movement-pattern slot showing what's already been done, tap through to that pattern's readiness-sorted exercise pool → existing Lift Detail to actually log) → Abort/Complete. Viewing a **completed** session also exposes editable start/end times (2026-07-17) — a completed session's own span now drives the Metrics "Workout Duration" chart in preference to summing individual lift-log Track Time windows, which could badly undercount the real workout. A sorter, not a scheduler — logging works normally from anywhere whether or not a session is active, matches are derived live from same-day logged sessions rather than requiring an explicit completion step. Phase 3 (multiple saved templates, CSV import/export, a Workouts-tab day annotation) is scoped but not built, see `10_WORKOUT_PLANNER.md`.

**Lift detail was substantially reworked (2026-07-15 to -17).** The near-term prediction box ("Next Heavy Set," renamed) now projects a weight at the rep count the user actually tends to go heavy at, from same-rep-count history only — no more converting between rep ranges via Epley, which was producing bad estimates on near-failure multi-rep sets. The trend chart ("Heavy Set History," renamed) plots literal per-session heaviest weight (never a formula), dot size encoding that set's rep count, with a dashed e1RM-shaped trend line re-centered onto the raw-weight scale rather than plotted on its own axis. **All decay/detraining-curve modeling was removed app-wide** — Predicted 1RM is now just the best of the last 3 sessions, no taper — per the user's call that it implied more scientific rigor than the underlying math actually supports at this level. The Goal gauge's custom-goal path is a full **log**, not a single overwritable value: multiple labeled targets over time, the most recent driving the gauge, older ones browsable/deletable via a history sheet, selectable per-lift alongside (or instead of) a published bodyweight-ratio standard via a Standard/My Goal toggle. The True Max line now also shows the rep count it was hit at.

**Metrics gained two new self-contained features (2026-07-17).** **Progress photos** — a date-stamped image log, shown as a day-stacked "pile" album (photos pinned to a shared bottom-left corner, rotated per photo, capped at 3 shown and always the most recent), tap a stack to swipe just that day or a toolbar icon to swipe every photo; delete and a download-via-share-sheet action on each. **The metric builder** — unlimited user-defined metrics (plain number / a 0-5 scale with a chosen icon — flame, star, dot, heart, bolt, moon, drop — / named classes with a "Mood" preset), each with its own trend chart and a once-vs-multiple-per-day setting per metric. **Every** metric card, built-in and custom alike (including Soreness and the derived Workout Duration chart), now has a notebook icon opening a focused single-metric history popup — deliberately not a jump to the Days tab, since browsing "every Steps reading ever" and "everything logged today" are different jobs.

**Home gained layout editing and a Checklist widget (2026-07-18).** An edit toggle in the AppBar turns every Home section into a drag-reorderable, swipe-to-remove list (`SliverReorderableList` + `Dismissible`, drag limited to a dedicated handle icon so it doesn't fight the swipe gesture), with a "+" menu while editing to add back anything hidden — order/visibility persists as one setting (`home_widget_order`, an ordered list of `HomeWidgetId`s; unset falls back to the original default order). **Checklist** is a new small fixed list of recurring reminders (distinct from a one-off todo list) — tap-to-check rows that strike through and reset automatically every calendar day (`TodoItem.lastCheckedDate == today`, no background job needed), a batch edit sheet matching the lift-log set-row editor's shape, and an optional per-item time that schedules a real daily-repeating local notification (`flutter_local_notifications`, inexact scheduling to avoid Android 12+'s heavier exact-alarm permission). See `02_SCREEN_home.md` "Layout editing" and "Checklist" for the full mechanics.

## Automated tests
`flutter test` covers the pure-logic services — no DB, no widgets, just known inputs against expected outputs (`TrendEngine.predictNextAtCharacteristicReps`/`predictedOneRepMax`, `StrengthStandards`' tier math, `BodyweightRepStandards`, `EffortDisplay`, `ReadinessEngine.toBars`/`readinessForExercise`/`suggestPrimedLifts`/`computePatternRecency`, `LiftSet`/`SessionWithSets` e1RM math including the bodyweight-adjusted path, `WorkoutPlanService.matchedSessions`/`progressFraction`). Deliberately scoped to what's cheap and stable to test — no widget/integration tests yet, no DB-backed repository tests (would need a fake/in-memory sqflite setup, not done). Run via `flutter test` from `TerpinLift/`. First real test coverage in the app; added specifically so the next time the smart-trends math gets touched, a regression shows up immediately instead of weeks later mid-workout.
