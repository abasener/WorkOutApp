# Screen: Quick Log (center FAB)

Single entry point for logging anything, opened from the bottom-nav FAB from any screen. Bottom sheet, per the starter bundle's modal-bottom-sheet pattern.

## Flow — implemented
1. Tap FAB → sheet with a picker: **Lift / Weight / Sleep / Steps / Soreness**. (**Cycle was removed from this picker** — it's only logged from the calendar on its own Cycle detail screen off Metrics, since a FAB button felt like the wrong place for something meant to stay out of casual view.)
2. Each choice opens the minimal form for that type:
   - **Lift**: pick exercise (dropdown) → enter set(s): reps, weight (unit-aware, labeled with the current lb/kg setting), a "Reps left" field (with the shared "i" info-tooltip) → optional notes → "add another set" or "Done." Sheet is sized to at least half the screen height (previously it just fit its content, which felt cramped).
     - **Picker defaults to pinned exercises only** (`03_SCREEN_lifts.md` "Pinned lifts"), not the full ~75-exercise seeded library. Still always includes `preselected` (passed when opened from a specific lift's detail page) even if unpinned, so that path never shows a picker missing its own exercise. **2026-07-15: became searchable** (`ExercisePickerField`) — typing searches every exercise by name, pinned or not, so an unpinned lift no longer needs a detour through the Lifts tab.
     - **"Reps left" is a UI-only inversion of stored RPE** (`EffortDisplay.toDisplay`/`.fromDisplay`) — after real gym use, the user pointed out most lifters think in "how many reps did I have left," the opposite direction from the traditional RPE convention (10 = to failure) this app started with. Storage and every downstream formula (`ReadinessEngine`, `predictNextAtCharacteristicReps`, training composition) still use the original RPE direction untouched — only the entry fields and the one raw-value display (Lift detail history rows) convert at the boundary. **Revised 2026-07-15**: entry domain is 0-10, not 1-10 (0 = "tried an extra rep and failed," matching the user's own convention), and 9/10 reps-left both collapse to the RPE floor (1) rather than getting distinct values — past ~8 reps left the distinction carries no real information. See `08_GLOSSARY_AND_SCIENCE.md` RPE entry for the full reasoning.
     - **Track time toggle** (default ON) in the form header: opening the form silently captures a wall-clock timestamp; hitting "Done" captures the completion timestamp; both are stored on the session only if the toggle is on. No visible countdown/timer UI. Dismissing the sheet without hitting Done discards everything (nothing partial gets written). See `00_UX_DESIGN.md` for the full reasoning.
     - **Each set row has a remove button** (a small `−` icon left of the reps field, disabled when only one set remains — a session needs at least one) on both this form and `EditLiftSessionForm`. Added after real use turned up mis-taps on "add another set"; no reordering, just add/remove, per the user's call that reordering "doesn't really matter" here.
     - **"Calc" button next to the date pill** opens `PlateCalculatorSheet` (`lib/widgets/`) — a scratchpad popup, never writes back into the form (purely a mental-math aid, the user re-types whatever number they land on into the weight field). Two modes via a pill toggle:
       - **Barbell** — pick a bar weight (45/35 lb or 20/15 kg presets by current unit, or a typed custom value for anything non-standard like a hack squat sled or trap bar), then type plates for **one side only** — mirrored automatically (`PlateMath.totalWeight = barWeight + perSide × 2`), with a purely visual mirrored chip display either side of a "BAR" divider so it's clear what "one side" means. Free-typed plate weights rather than a fixed preset set — plates range from 2.5 to 45+ lb across different gyms/units, too many to enumerate as buttons, per the user's call.
       - **Calc** — a plain 4-function calculator (+ − × ÷), left-to-right evaluation like a physical calculator (no operator precedence). Arithmetic lives in a pure, unit-tested `CalculatorEngine` (`lib/services/`) separate from the keypad UI.
   - **Weight**: single numeric entry (bodyweight, unit-aware).
   - **Sleep**: entered as **separate Hours + Minutes fields** (not one decimal-hours box) — more natural to type than "7.5." Combined to decimal hours on submit/display decomposed back into h/m on edit; storage (`MetricType.sleepHours`) and every downstream trend calculation are unchanged, this only touches the entry/edit UI.
   - **Steps**: numeric entry.
   - **Soreness**: opens `SorenessBodyMapForm` instead of a number field — tap a body region on a heatmap diagram, pick a 0-5 flame level for that region, save; repeatable per region, per session. See `00_UX_DESIGN.md` "Soreness body map."
   - **Every quick-log form has a `DatePickerField`** (shared widget) defaulting to today but backdatable to any past date — capped so you can't log a future date. Added so a missed entry (e.g. logging yesterday's steps once the day is over) doesn't have to be entered as "today."
3. Submit → `AppServices.signalReload()` so Home/Lifts/Metrics reflect the new entry immediately.

## Design notes
- Every numeric/scale field that isn't self-evident gets the shared `InfoTooltip` widget (RPE, soreness).
- Keep this screen fast — it's meant to be used mid-workout or in passing, not a place to browse/read data (that's Home/Lifts/Metrics).
